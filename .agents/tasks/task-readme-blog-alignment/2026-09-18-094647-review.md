## Compose plan-id table vs UPDATE-COMPOSE.md note 3

`platform/README.md` §7 introduces its built-in plan table with "来源：docs/UPDATE-COMPOSE.md 注意事项第 3 条", but the two don't agree. Note 3 lists eight pairs:

```
h200-tp8-eagle              -> docker-compose-tp8-h200.yaml
h200-tp8-eagle-0731         -> docker-compose-tp8-h200-0731.yaml
b300-tp8-eagle              -> docker-compose-tp8-b300.yaml
b300-tp8-eagle-0731         -> docker-compose-tp8-b300-0731.yaml
b300-pd-2p2d                -> docker-compose-pd-2p2d.yaml
b300-pd-2p2d-0731           -> docker-compose-pd-2p2d-0731.yaml      (no such file)
b300-pd-3p1d                -> docker-compose-pd-v4flash-b300.yaml
b300-pd-3p1d-0731           -> docker-compose-pd-v4flash-b300-0731.yaml  (no such file)
```

Only seven yaml files exist in `platform/lambda/deployer/compose-files/`; the two `-0731` PD entries in note 3 are dangling. The README table drops those two and instead lists `b300-tp8-eagle-0731-nodspark -> docker-compose-tp8-b300-0731-nodspark.yaml`. That row is the file-accurate choice — all seven README rows map to real files, and `docker-compose-tp8-b300-0731-nodspark.yaml` is the one on-disk file note 3 forgot — but the id `b300-tp8-eagle-0731-nodspark` is not what note 3 says, so the "source: note 3" attribution is false as written. There is no plan-id↔filename mapping anywhere in the Lambda or frontend code (`grep` across `platform/lambda` and `platform/frontend/src` finds none), so neither table can be validated against code; the ids are a documentation convention. Recommend dropping the note-3 attribution (or reconciling both tables and fixing the two dangling ids in note 3), and adding a one-line caveat that plan ids are a doc convention rather than code-enforced. (likely)
