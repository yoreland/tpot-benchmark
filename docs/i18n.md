# 多语言 (i18n) 支持

tpot-benchmark 的命令行脚本支持多语言输出，默认回退到英文。本文档说明如何
切换语言、i18n 层的工作方式，以及如何新增一个 locale。

对应 issue: [#9 Add multi-language (i18n) support](https://github.com/yoreland/tpot-benchmark/issues/9)。

## 切换输出语言

语言解析按以下顺序，取第一个非空值，英文 (`en`) 为最终回退：

1. 命令行 `--lang <code>`（如 `--lang zh`）
2. 环境变量 `TPOT_LANG`
3. 环境变量 `LC_ALL` / `LANG`（`zh_CN.UTF-8` 会被规范化为 `zh`）
4. `en`（回退）

示例：

```bash
# 显式中文
./scripts/run-benchmark.sh --lang zh --help

# 显式英文
./scripts/run-benchmark.sh --lang en --help

# 跟随环境（zh_CN.UTF-8 -> zh）
LANG=zh_CN.UTF-8 ./scripts/run-benchmark.sh --help

# 用环境变量固定
export TPOT_LANG=zh
./scripts/run-benchmark.sh --help
```

未知语言（如 `--lang jp`，没有对应 locale 文件）会静默回退到英文。

## 工作方式

- 文案目录以 JSON 存放在 `locales/<lang>.json`，key 为点分命名（如
  `usage.opt.region`），value 为可带 `%s` 占位符的模板串。
- 可复用的 shell 库在 `scripts/lib/i18n.sh`：
  - `i18n_init "<lang-or-empty>"` —— 解析语言并加载目录（含英文回退目录）。
  - `t <key> [printf 参数...]` —— 取出 key 对应文案并展开 `%s`/`%d`，所选语言
    缺某 key 时回退英文，英文也缺时原样打印 key（便于发现拼写错误）。
  - `i18n_lang` —— 回显最终解析出的语言码（诊断/测试用）。
- 依赖 `jq`（本仓库其它脚本已在用）。

脚本里的接法（见 `scripts/run-benchmark.sh`）：

```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/lib/i18n.sh"
i18n_init "$LANG_FLAG"      # LANG_FLAG 来自预扫描的 --lang
echo "$(t error.cluster_unreachable)"
```

## 新增一个 locale

1. 复制 `locales/en.json` 为 `locales/<code>.json`（例如日语用 `locales/ja.json`）。
2. 翻译每一个 value；**保留全部 key 和其中的 `%s` 占位符顺序**。
3. 更新文件头部的 `_meta`（`language` / `name` / `fallback` 置为 `false`）。
4. 跑测试验证：

```bash
bash tests/run-tests.sh      # 包含 i18n 子套件（用例 31）
bash tests/test_i18n.sh      # 也可单独跑
```

### key 集必须对齐

`tests/test_i18n.sh` 会断言 `en` 与其它 locale 的 **key 集完全一致**。新增 key
时必须同时加到所有 locale 文件里（all-or-nothing）。缺失的 key 在运行时会回退到
英文而不会报错，但测试会把 key 集不一致判为失败，避免漏翻。

### 翻译注意

- 不要在模板里手工拼接复数/数字（如 `{n} item{s}`）；把数量作为 `%s` 传入，让
  各语言的文案自己处理。
- `verdict.pass` / `verdict.fail` 这类是对外契约字段（会进 JSON 结果），各语言
  保持 `PASS` / `FAIL` 原值，不要翻译。
